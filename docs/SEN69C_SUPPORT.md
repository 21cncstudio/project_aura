# SEN66 / SEN69C support

Implemented locally on `idf-6.1-migration`, 2026-09-12. This is a software
candidate; an actual SEN69C has not been connected or qualified.

## Selection and ownership

`Sen6x` identifies the module at `0x6B` with the product-name command `0xD014`
and reads its serial number with `0xD033`. Each complete 48-byte response is
CRC checked, bounded and required to contain terminated printable ASCII.
Only exact `SEN66` and `SEN69C` names are accepted. An unknown product is
reported as unsupported. No model is guessed from an address ACK or from
failed measurement commands.

`Sen66` retains its existing implementation. The independent `Sen69c` driver
uses Aura's native I2C transport, with shared framing in `Sen6xTransport`.
Both are included in each hardware profile's firmware. There is no additional
FreeRTOS task, Arduino Wire instance or new dependency.

The main-module probe precedes external HCHO detection. SEN69C supplies its
own HCHO; SFA30/SFA40 detection and polling are skipped. SEN66 retains the
existing external SFA path. If the main module is absent after bounded
startup attempts, the standalone SFA path remains available. A failing
integrated HCHO channel never silently switches to an external sensor.

Boot diagnostics show the selected model, and logs record its serial number.
The existing SFA40 diagnostic endpoint identifies SEN69C as the active HCHO
source while keeping its `active_sfa40` flag false.

## Driver behavior

- SEN69C measurements use `0x04B5`, ten words / 30 bytes with CRC. Word 8 is
  unsigned HCHO in tenths of ppb; word 9 is signed CO2. `0x7FFF` CO2 and
  `0xFFFF` HCHO are missing values. PM, RH/T and gas-index scaling remain
  compatible with the existing application data fields.
- CO2 and HCHO availability have separate clocks. Startup CO2 conditioning
  lasts 24 seconds; HCHO starts after 60 seconds. Missing data beyond the
  bounded initial window is unavailable, not permanent warmup. These are
  first-data rules, not a claim that full specified accuracy is already met.
- Initialization and the normal measurement read sequence use cooperative
  deadlines. MCU-only restarts wait through a conservative conditioning
  interval before STOP/reset/configuration. Failed STOP operations can be
  retried after the same bounded safety interval.
- Actual ASC is read and compared with the requested setting, changed only
  when necessary, then verified. Initialization does not assume that a reset
  made ASC enabled. This avoids depending on conflicting persistence wording
  in the supplier's PDF and driver header.
- FRC is rejected before three minutes of continuous operation. Measurement
  is restarted after an attempted calibration even if its correction fails.
  Stop/configuration is rejected during initial CO2 conditioning.
- Pressure compensation and enclosure temperature/humidity offsets are
  retained. Updates cannot overwrite an outstanding identity or measurement
  response. A pending temperature/pressure update is retried without starving
  measurement polling.
- CO2-1 status bit 12 and HCHO bit 10 are handled separately. Repeated
  transport errors stop warmup presentation, and the manager's existing
  freshness checks invalidate stale samples. Routine transient read failures
  resume through polling; there is no new infinite reset/reprobe loop.
- A failed START/STOP/reset during an explicit ASC, FRC or VOC-reset operation
  rearms the existing finite five-attempt initialization budget once. SEN69C
  keeps its conservative 24-second guard for an unknown measurement state.
  Failed attempts do not rearm that budget again. Previous readings are
  invalidated while the main driver is unavailable.
- Sticky device errors are logged and read/cleared with `0xD210`, at most once
  per 30 seconds, including failed clear attempts. D210's pre-clear response
  cannot make a channel healthy: its mask remains until two consecutive later
  1 Hz status reads no longer report that error. Persistent errors remain
  masked; this mechanism does not reset the sensor or restart measurement.
- SEN69C VOC state uses `/sen69c_voc_v1.bin`, tagged with serial number and
  record version. It never restores the legacy SEN66 `/voc_state.bin`.
  The existing SEN66 persistence behavior remains unchanged.

Offset changes received during initialization are replayed to the selected
driver before its first sample is published. PM0.5 retains its last fresh
sample while the cooperative number-concentration read is pending; a failed
command/read or an applicable device fault still invalidates that sample.

## EEZ and CO2 warmup

The user's current EEZ was copied into canonical `ui/aura-lvgl.eez-project`,
preserving its authored content and adapting only the build/font paths and
the new label's initial hidden flag. The original user file was left intact.
`label_co2_warmup` is generated by installed EEZ Studio 0.27.1 for LVGL 9.5.

`SensorData.co2_warmup` controls the label independently of VOC/NOx and HCHO.
Old CO2 values are invalidated as conditioning starts; value and unit are
hidden while the warmup label is shown. Text uses the existing localization.
The flag is also exposed by the state HTTP API. Existing HTTP/MQTT HCHO
measurements and discovery are reused.

The EEZ postprocessor preserves the label's hidden startup state even if a
future editor build only sets `hiddenInEditor`. A unit test checks this
invariant and idempotence. No generated font subsets were replaced.

Before integrating/releasing: qualify SEN66 regression and actual SEN69C on
both relevant board profiles; check cold power-on, MCU-only restart, touch
response, channel readiness, bus loss/recovery, pressure and ASC readback.

tests. SEN69C has a different CO2 accuracy specification from SEN66.
