# Project Aura v1.2.0 beta

Local release candidate for the Aura AQ 4.3-inch and 7-inch controllers.
This document does not authorize publication or qualify a newly built image.

## Changes

- Production memory monitoring now takes one boot snapshot instead of walking
  the full heap every 15 minutes. Controlled testing linked the periodic walk
  to the observed display recovery cadence.
- Removes temporary private RGB/DMA instrumentation and the retired GT911
  diagnostic build. Normal display/touch counters, framebuffer protection and
  LVGL fail-stop remain.
- Uses the accepted GT911 address selection: `0x14` on 4.3-inch and `0x5D` on
  7-inch, without the diagnostic startup probes.
- Includes the updated EEZ interface, CO2 value/unit layout and centered
  button labels.
- Includes the reviewed startup backlight, framebuffer ownership, logging,
  sensor-sample validation and diagnostic-report work from the beta sequence.
- Preserves the original reason when a rejected built-in OTA request is
  replayed after its physical confirmation was consumed.
- Renames the 7-inch hardware profile from `7_dual_i2c_scl6` to `7_dual_i2c`.
  New build IDs and public filenames use `7-dual-i2c`.

## Hardware and compatibility

The environments remain `project_aura` and `project_aura_7`; the targets remain
`aura-aq-v1` and `aura-aq-7-v1`. Both use native USB. The 7-inch sensor bus
remains I2C1 on SDA GPIO44/SCL GPIO6; the panel bus remains I2C0 on GPIO8/9.
The two boards require separate BINs and packages.

Historical signed packages retain their original profile and bytes. Aura Link
and the installer need backward-compatible support for both 7-inch profile
names before using the renamed candidate. The rename does not open the
7-inch service OTA, Stable, Recovery or new-version publication gates.

## Validation boundary

The preceding EEZ candidate completed an overnight observation; the operator
confirmed normal screen/touch operation and a subsequent physical cold boot.
Those results apply to the preserved `ee3d8a7` dirty candidates for each board,
not automatically to a new `1.2.0-beta` BIN or Full Install package.

The final source commit, build identities, hashes, local verification and
remaining physical checks are recorded separately in the
[local preparation record](LOCAL_1_2_PREPARATION_20260903.md).
