# Project Aura v1.2.0 beta.1

Beta update for the Aura AQ 4.3-inch and 7-inch controllers.

## Changes since v1.2.0 beta

- Adds automatic support for both production and B4 revisions of the Sensirion
  SFA40 protocol. Production is detected first, with the matching ID,
  measurement command, response length and status-byte layout retained for
  subsequent reads.
- Sends STOP before SFA40 protocol detection and waits 700 ms so identification
  also works after an ESP software restart while the sensor remains in
  continuous-measurement mode.
- Uses a 1 ms command-to-read delay and waits at least 1000 ms after START
  before the first SFA40 measurement.
- Reports the selected SFA40 protocol and up to five serial-number words in the
  diagnostics endpoint.
- Changes the normal SFA40 and SFA30 measurement cadence to one read per second.
- Preserves the existing automatic SFA30 fallback when SFA40 is not present.

## Hardware and compatibility

The environments remain `project_aura` and `project_aura_7`; the targets remain
`aura-aq-v1` and `aura-aq-7-v1`. The 7-inch profile remains `7_dual_i2c` and
uses its separate target-specific package.

## Validation boundary

Native tests cover production and B4 identification, measurement commands,
response lengths, status-byte layouts, CRC/read failures, required delays,
millis wraparound and SFA30 fallback. Both production firmware environments
build successfully.

Application-only smoke testing passed on the two local reference boards: the
4.3-inch board detected a production SFA40 and the 7-inch board continued to
use SFA30. Display, touch and sensor diagnostics remained healthy, and the
observed sensor cadence was approximately one read per second. A physical B4
SFA40 has not yet been qualified in this public Project Aura build and remains
part of beta-tester validation.
