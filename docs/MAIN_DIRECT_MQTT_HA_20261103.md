# Прямой MQTT Aura main → Home Assistant и закрытие ревью, 2026-11-03

Разрешение владельца: закрыть три пробела тестов, проверить телефон на точном
BIN, проверить Aura → наш HA напрямую без Hub и оставить 4,3″ подключённой.
Дополнительно явно разрешены сохранённый доступ HA на Mac, чтение нужных
настроек авторизации/ACL и отдельная MQTT-учётка. Владелец сейчас не у ПК;
дальнейшая настройка проводится удалённо. Push/публикации нет, 16 МГц.
7″ остаётся на прежнем восстановленном Hub и в этом проходе не прошивается.

Evidence: `build/sta-regressions-mqtt-ha-20261103/` (R).

## Тесты и уточнение независимого ревью

Рабочая логика NetworkManager не изменена. A51 теперь проходит успех,
обнаружение потери связи и автоматический reconnect внутри исходных 30 с;
проверяет предупреждение уже в CONNECTING. A54 проверяет событие между
попытками, задержавшийся callback и callback внутри disconnect перед OFF.
Используется холодный soft-retry, где сброс интерфейса не маскирует дефект.
A55 различает AUTH_FAIL/ASSOC_FAIL и MIC/4-way-handshake ошибки, включая
исчерпание ASSOC_FAIL retries. Окончательный полный стенд: 389 PASS, 0 FAIL.
Три отрицательных контроля пойманы конкретными assertions, не timeout или
ошибкой сборки: потеря reset перед новой попыткой, тишина для любых причин,
сохранение окна после первого успеха. `R/mutation-controls.json`.

Промежуточные неудачи стенда сохранены: сначала A55 ошибочно требовал Warn
для AUTH_LEAVE/inactivity; эти причины были Info ещё до нового окна.
Поэтому формулировка ревью «остальные причины всегда Warn» слишком широка.
Затем первая копия мутанта не содержала HTTP shim и не собралaсь; это не
засчитано. Удаление одного reset при обычном forced-reset старте выживало
из-за дублирующего сброса; окончательный тест использует холодный soft retry.

## Телефон на 184845b и успешные медленные ответы

Владелец включил AP на 4,3″ через штатный экран. Pixel 3 открыл системный
captive-портал, один UI Rescan завершился, Meotida выбрана из списка,
пароль введён из приватной копии и форма отправлена настоящей кнопкой.
Pixel сам вернулся в Meotida; Aura на точном 184845b вернулась в STA,
последующий HTTP smoke 8/8. Идентификатор через AP проверен самим Pixel.
Промежуточная страница после submit не захвачена: captive-окно закрылось.

Владелец заметил HTTP slow write. Журнал этого опыта: `/` 818 мс,
`/wifi` 1263 мс, `/save` 699 мс (максимум одной операции отправки).
В WebResponseUtils эта строка возможна только после успешного finish;
ошибка идёт по отдельной ветке HTTP interrupted. Это не доказательство
радиопричины медленной передачи и не отрицание ограничений скорости 4,3″.

По явному запросу владельца успешные медленные отправки переведены с Warn
на Debug. Счётчики slow_count/max_write и история настоящих ошибок сохранены.
Ошибки/обрывы остаются Warn. Реальный Logger по умолчанию Info, поэтому
успешная задержка не попадает в обычный журнал и пользовательские alerts.
Используется существующая фильтрация; проверены локальный Logger и официальное
[описание уровней Espressif](https://developer.espressif.com/blog/2025/09/espressif_logging/).
Native WebResponseUtils/WebStreamState: 15/15, включая реальный Logger,
сохранение Warning для ошибки, отсутствие нового alert при медленном успехе
и доступность этого сообщения при Debug. Таймауты/транспорт не менялись.
Нужны новые точные BIN и повтор короткого телефонного сценария.

## Подготовка прямого MQTT

На Mac до изменений активны пять служб, HA содержит 179 entities.
Используется существующий Mosquitto: LAN `192.168.88.20:18883` → локальный
broker 1883 → HA. Порт по историческим причинам называется Hub socket,
но это обычный TCP proxy к брокеру; физический Hub в новом пути не участвует.
Создана отдельная учётка `aura_main_046f48`, base topic `aura/046f48`.
Права устройства ограничены своим state/commands и 54 точными discovery
topics его device ID; HA добавлены чтение этого namespace и запись commands.
Прежние account blocks сохранены, password/ACL заранее скопированы в
root-only backup. Только SIGHUP, без рестарта брокера. Пять служб active.
Пароль хранится в root-only `/etc/aura-lab/aura-main-046f48.json`; не в Git.
Сверены официальные [MQTT discovery HA](https://www.home-assistant.io/integrations/mqtt/)
и [ACL/reload Mosquitto](https://mosquitto.org/man/mosquitto-conf-5.html).

MQTT на устройстве ещё не включён, проверка публикаций/команд/HA впереди.
