# Pixel 3 и Wi-Fi кандидата 56ea11e, 2026-11-03

На 4,3″ пройдена ограниченная телефонная проверка текущего `56ea11e`, 16 МГц: системное captive-окно Android, Chrome, повторный поиск сетей и обычное сохранение домашней сети. Новый код и BIN не создавались. Это не полная приёмка релиза.

Evidence: `build/pixel3-setup-20261103/` (подготовка телефона) и `build/pixel3-ap-56ea11e-20261103/` (проверка платы). Приватные инвентаризации телефона, конфигурации и дампы остаются только в ignored evidence, не в Git.

## Телефон

Владелец выделил старый Pixel 3 и разрешил обновления, очистку данных YouTube Music и удаление пяти названных приложений. После разрешённой очистки и обновлений оставалось около 9,6 ГиБ свободного места вместо первоначальных 247 МиБ. Иные приложения и Google-аккаунты не удалялись: просьбу выйти из основного аккаунта владелец отменил, решив сделать это самостоятельно.

- Android 12, `SP1A.210812.016.C1`; штатный экран обновлений сообщает об окончании регулярной поддержки. ОС не перепрошивалась.
- Chrome обновлён через Google Play: `119.0.6045.163` → `156.0.8078.79`.
- Android System WebView: `125.0.6422.165` → `156.0.8078.47`; активный provider проверен отдельно.
- USB/ADB работает; телефон заряжается, финальное наблюдение — 21%. SIM отсутствует. Сценарий переключения на мобильный интернет этим телефоном не проверен.

## Точный объект проверки

Перед изменением настроек снят свежий полный образ 16 МиБ. Активный app slot побайтово совпал с сохранённым кандидатом 4,3″:

`689412f8138c28b1a5cfe8d404a787f7a6db6d3436685fcbeb4f619228cc622e`.

Устройство идентифицировано по native USB MAC `94:A9:90:04:6F:48`, COM5, и live API `56ea11e` / `4_3` / `aura-aq-v1`. Приложение не записывалось. Для входа в AP временно изменены только два config-файла LittleFS; исходные байты сохранены. Это загрузки после USB/reset, не физическое снятие питания.

Rescan запускался нажатием ссылки. Возврата списка дожидались через UI: запросы стенда не заменяли собственный XHR polling страницы. Время включает задержки ADB/UIAutomator и является верхней оценкой времени завершения, а не точной сетевой метрикой.

Обычное сохранение выполнено в системном captive-окне с выбранным SSID и введённым паролем. После подтверждения Android автоматически закрыл окно. На `phone/captive-save-2.png` видна часть текста `Starting…` во время анимации закрытия; отдельного полного неподвижного кадра подтверждения нет. Успешный переход подтверждён serial и live API. В Chrome проверены открытие и Rescan; отдельное сохранение формы в Chrome не запускалось.

## Ошибки стенда и восстановление

Первый дополнительный HTTP-запрос через stdout ADB не разобрался как chunked: прежняя нормализация `CRCRLF` не учитывала добавленный `CR` перед одиночным `LF` в HTML и нарушала длины chunks. Ошибочный сырой ответ не сохранился, поскольку старый helper записывал его после успешного разбора; этот запрос не засчитан ни как PASS, ни как доказанный сбой firmware.

Причина отдельно воспроизведена на неизменном файле: исходные 27 969 байт через stdout ADB превратились в 28 555 байт, точно совпав с добавлением `CR` перед каждым `LF` (`phone/adb-stdout-control.json`). Исправленный helper перенаправляет ответ в файл на Android и забирает его бинарным `adb pull`, без нормализации. Все 15 последующих исходных HTTP-потоков сохранены и полностью разобраны.

Первая финальная проверка текстового списка сетей остановилась на лишних пустых строках из разных способов текстовой записи. После нормализации пробелов все 137 непустых записей исходного и конечного списка совпали; добавленных или удалённых исходных сетей нет. Временная сеть Aura удалена, тестовая вкладка Chrome закрыта, временные файлы стенда на Pixel удалены.

Два исходных config-файла 4,3″ восстановлены побайтово, LittleFS проверен чтением обратно. При восстановлении другие файлы не менялись. Финально 4,3″ работает на том же `56ea11e` в домашней сети, `display_sync_fault=false`. Оба своих serial-журнала STOPPED, TX=0, fatal=[].

7″ не прошивалась и не перезапускалась: финально исходный Hub `afd6f05-7-dual-i2c-ram-a0`, uptime 55 321 с, `display_sync_fault=false`. Это проверка доступности прежней прошивки, не приёмка нового кандидата 7″. Mac и его службы не трогали; push и публикации не было.
