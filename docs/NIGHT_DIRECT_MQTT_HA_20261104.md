Это **таймауты чтения на стороне наблюдателя**, а не новые предупреждения `HTTP body timeout` в журнале платы. Они возникли без нашей искусственной нагрузки. Причина не определена: по этим данным нельзя приписать её прошивке, Wi-Fi или клиенту. Оба запроса восстановились в последующих опросах без вмешательства; MQTT продолжал передавать данные, новых предупреждений и сброса uptime не появилось. После второго таймаута до конца наблюдения новых ошибок HTTP нет.

Три старых предупреждения исключены из ночных: MQTT `ts_ms=1628890/1628894` и Web `ts_ms=2394408`, вызванные предыдущими контролируемыми тестами. Счётчики web abort=0, slow=3, MQTT publish deferred=5 за ночь не изменились.
